# MongoDB Notes
### 1. The _id Field
Every document in a MongoDB collection has a unique _id.
- Unique ID: Two documents in the same collection cannot have the same _id.
- Default Type: MongoDB usually creates _id as an ObjectId if you do not provide one.
- Primary Key: The _id field works like a primary key in SQL.
- Fast Search: MongoDB automatically creates an index on _id, making searches by _id efficient.
- Document Operations: Use _id to find, update, or delete a specific document.
- Cannot Be Changed: Once a document is inserted, its _id cannot be changed.
### 2. What Is an ObjectId?
An ObjectId is MongoDB's default ID type. It is 12 bytes long and is usually shown as a 24-character hexadecimal string.
- 1 byte = 8 bits
- 1 byte is represented by 2 hexadecimal characters
ObjectId Structure
Part	Size	Purpose
Timestamp	4 bytes	Stores the creation time in seconds
Random value	5 bytes	Helps make IDs unique across machines and processes
Counter	3 bytes	Helps distinguish IDs generated by the same process


Note: The timestamp can help estimate when an ObjectId was created, but it should not be treated as an exact record of a document's creation time.

## Projection in MongoDB

### What Is Projection?

**Projection** Projection is the processs of  selecting a specific fields that  we want to retreve from our documents in monogodb, while including and excluding others fields

By default, `find()` returns all fields. Projection lets us return only the data we need.

### 1. Include Specific Fields

Use `1` to include a field.

```javascript
db.users.find({}, { name: 1, email: 1 })
```

**Output:**
```javascript
{ _id: ObjectId("..."), name: "Rahul", email: "rahul@example.com" }
```

> **Note:** The `_id` field is included by default.

### 2. Exclude the `_id` Field

Use `0` to exclude a field.

```javascript
db.users.find({}, { name: 1, email: 1, _id: 0 })
```

**Output:**
```javascript
{ name: "Rahul", email: "rahul@example.com" }
```

### 3. Exclude a Specific Field

Use `0` to hide a field.

```javascript
db.users.find({}, { age: 0 })
```

This returns all fields except `age` and `_id` remains included.

### 4. Important Rule

You generally cannot mix `1` (include) and `0` (exclude) in the same projection, except for `_id`.

**Incorrect:**
```javascript
db.users.find({}, { name: 1, age: 0 })
```

**Correct:**
```javascript
db.users.find({}, { name: 1, _id: 0 })
```

### 5. Benefits of Projection

- **Less data:** Returns only the required fields.
- **Better performance:** Reduces the amount of data sent over the network.
- **Cleaner results:** Avoids unnecessary information.
- **Useful in production:** Helps return only the data an application needs.

### Quick Revision

- `1` = Include a field.
- `0` = Exclude a field.
- `_id` is included by default.
- You can exclude `_id` while including other fields.
- Use projection to return only the required data.

## . Ordered vs. Unordered Insert

### What Happens If an Error Occurs During Multiple Inserts?

When inserting multiple documents using `insertMany()`, MongoDB handles errors differently depending on the `ordered` option.

### 1. Ordered Insert (Default)

By default, MongoDB uses ordered inserts.

- Documents are inserted in sequence.
- If an error occurs, MongoDB **stops inserting the remaining documents**.
- Documents inserted before the error remain inserted.

**Example:**

```javascript
db.users.insertMany([
  { name: "Rahul", age: 25 },
  { name: "Amit", age: 28 },
  { _id: 1, name: "Priya", age: 22 }
])
```

If `_id: 1` already exists, the duplicate key error stops the remaining inserts. The example assumes the error occurs on the third document.

### 2. Unordered Insert

Use `{ ordered: false }` to continue inserting other documents even if an error occurs.

```javascript
db.users.insertMany(
  [
    { name: "Rahul", age: 25 },
    { _id: 1, name: "Amit", age: 28 },
    { name: "Priya", age: 22 }
  ],
  { ordered: false }
)
```

If the second document causes a duplicate key error, MongoDB attempts to insert the third document as well.

### 3. Comparison

| Feature | Ordered Insert | Unordered Insert |
|---|---|---|
| Default | Yes | No |
| Stops after an error | Yes | No |
| Attempts remaining inserts | No | Yes |
| Performance | May be slower | May be faster |
| Best use case | When insertion order matters | Bulk imports and product uploads |

### 4. When Should You Use Each?

- **Ordered:** When documents must be processed in sequence.
- **Unordered:** When importing CSV data, uploading product catalogs, or inserting large batches of independent documents.

### Quick Revision

- `ordered: true` is the default.
- `ordered: false` continues attempting the remaining inserts after an error.
- A failed document is not inserted, but other valid documents may still be inserted.
- Unordered inserts do not guarantee insertion order.
